# Yin-Panel Helper

[English](../../README.md) | [简体中文](../zh-CN/README.md) | [繁體中文](../zh-TW/README.md) | [日本語](../ja-JP/README.md) | [한국어](../ko-KR/README.md) | [Deutsch](../de-DE/README.md) | [Français](../fr-FR/README.md) | [Español](../es-ES/README.md) | [Português (Brasil)](../pt-BR/README.md) | **Русский**

Необязательное расширение Chrome Manifest V3 для Yin-Panel. Оно получает настоящие байты значков сайтов при импорте закладок, когда обычные запросы браузера блокируются из-за CORS, переключается на публичные сервисы значков и добавляет настраиваемое перенаправление новой вкладки. Yin-Panel продолжает работать без него, используя собственные серверные значки и текстовые запасные варианты.

## Установка

1. Откройте `chrome://extensions`.
2. Включите режим разработчика.
3. Выберите **Load unpacked** и укажите этот каталог.
4. Перезагрузите Yin-Panel перед запуском импорта закладок.

## Разрешения

- `storage` — хранит целевой URL новой вкладки.
- `host_permissions: ["<all_urls>"]` — расширение запрашивает данные значков напрямую с сайтов закладок.
- Разрешения на камеру, микрофон, геолокацию, уведомления или устройства не запрашиваются.

## Перенаправление новой вкладки

`chrome_url_overrides` направляет каждую новую вкладку на `newtab.html`, который сразу перенаправляет на сохранённый адрес. По умолчанию используется `https://panel.yiniot.com`, принимаются только URL со схемами `http` и `https`; недопустимые или отсутствующие значения заменяются значением по умолчанию. Целевой адрес задаётся из всплывающего окна на панели инструментов или на странице параметров.

## Получение значков

- Контент-скрипт отвечает только на сообщения с маркером `source: 'yin-panel'` и поддерживает типы сообщений `ping` и `fetch-icons`.
- Для каждой страницы service worker сначала обрабатывает собственные объявления значков сайта (`rel="icon"`, `apple-touch-icon`, `mask-icon`), а затем стандартные пути к значку в корне.
- Если они не срабатывают, он опрашивает публичные сервисы значков, создавая пул из восьми запросов для каждого доступного сервиса.
- Неудачные попытки возвращаются в Yin-Panel, который применяет собственные значки и текстовые запасные варианты; расширение не создаёт отдельный запасной значок.

## Разработка

| Файл | Роль |
| --- | --- |
| `service-worker.js` | Сообщения расширения, получение значков сайтов и публичные запасные варианты |
| `content-script.js` | Мост сообщений на стороне страницы, используемый Yin-Panel |
| `config.js` | Нормализация URL новой вкладки и целевой адрес по умолчанию |
| `newtab.html`, `newtab.js` | Переопределение новой вкладки и перенаправление |
| `settings.html`, `settings.css`, `settings.js` | Страница параметров и всплывающее окно на панели инструментов |
| `manifest.json` | Разрешения, точки входа, переопределение новой вкладки и регистрация контент-скрипта |

Этап сборки отсутствует; каждый файл загружается напрямую. Проверьте JavaScript и манифест командой:

```bash
node --check service-worker.js
node --check content-script.js
node --check config.js
node --check newtab.js
node --check settings.js
```

[AGENTS.md](../../AGENTS.md) описывает инварианты поведения, размещение тестов и правила безопасности. Приёмочные тесты уровня браузера находятся в [репозитории E2E](https://github.com/yinorg/yin-panel-e2e); служба Core находится в [yinorg/Yin-Panel](https://github.com/yinorg/Yin-Panel).

## Автоматическая публикация в Chrome Web Store

Рабочий процесс в `.github/workflows/publish-chrome-web-store.yml` запускается при отправке тега релиза. Он собирает временный пакет, задаёт версию манифеста пакета из тега, загружает его через Chrome Web Store API v2 и отправляет на проверку.

Chrome принимает от одного до четырёх разделённых точками числовых сегментов версии, поэтому теги должны выглядеть как `1.2.3` или `v1.2.3`. Необязательная ведущая `v` удаляется перед записью версии в манифест. Каждый сегмент должен находиться в диапазоне от `0` до `65535`, а версия должна быть больше текущей опубликованной версии.

### Разовая настройка

1. Включите Chrome Web Store API в проекте Google Cloud.
2. Создайте сервисный аккаунт Google Cloud и добавьте его адрес электронной почты в настройках аккаунта панели разработчика Chrome Web Store. См. [руководство по сервисным аккаунтам Chrome Web Store](https://developer.chrome.com/docs/webstore/service-accounts).
3. Настройте GitHub Actions Workload Identity Federation для этого репозитория. [Руководство по аутентификации Google GitHub Actions](https://github.com/google-github-actions/auth#setting-up-workload-identity-federation) описывает необходимые пул, провайдер и привязку IAM.
4. Добавьте следующие секреты репозитория:

   - `GCP_WORKLOAD_IDENTITY_PROVIDER`: полное имя ресурса провайдера, например `projects/123456789/locations/global/workloadIdentityPools/github/providers/yin-panel-extension`.
   - `GCP_SERVICE_ACCOUNT`: адрес электронной почты сервисного аккаунта.
   - `CHROME_WEBSTORE_PUBLISHER_ID`: идентификатор издателя из панели разработчика.
   - `CHROME_WEBSTORE_EXTENSION_ID`: 32-символьный идентификатор этого опубликованного расширения.

Например, опубликуйте версию `1.0.1` следующей командой:

```sh
git tag v1.0.1
git push origin v1.0.1
```

Рабочий процесс отправляет релиз автоматически, но проверка в Chrome Web Store может задержать момент, когда новая версия станет доступна пользователям.
